## ترتيب القراءة

- **المالكة أو من يستلم العمل:** `FINAL-REPORT.md` أولاً، ثم `04-STATE-AND-OPEN-ISSUES.md`، ثم `OWNER-DECISIONS.md`.
- **عضو في الفريق:** `01-RUNBOOK.md` ثم `SNAPSHOT.md`.
- **عند العمل مع Claude:** أرفق `02-AI-INSTRUCTIONS.md` و`01-RUNBOOK.md` ومجلد `tools/` في بداية كل محادثة (Claude لا يتذكر المحادثات السابقة).
- **قبل أي دفع:** `python tools\check_bot.py bot.db --strict` (انظر القسم 8، خطوة 5).

## ما تغيّر عن الأصل

إصلاحات (لا تغيّر المعنى):

1. إحالات خاطئة: «برومبت 1 من القسم الثالث» (لا يوجد برومبت بهذا الاسم؛ الجمل الجاهزة في القسم 15) و«الفحص والدفع (القسم الرابع)» (الدفع في القسم 8، والقسم 4 عن عرض الأسئلة) و«المرحلة الفحص في القسم الرابع».
2. صياغة بصوت الكاتب («خارج نطاق المصادر المتاحة لي»، «استطعت نسخه»، «لم أختر»، «ما وضعتُه») صارت محايدة.
3. أخطاء مطبعية: «من من يملك» → «ممن يملك»، «القسمين 11 خلال 12» → «القسمين 11 و12».
4. أُضيفت عناوين Markdown، وحُوّلت الجداول المفكَّكة (خلية في كل سطر) إلى جداول Markdown حقيقية. محتوى الجداول لم يتغيّر.
5. جدول المواد في القسم 11 استُبدل بـ `SNAPSHOT.md` المولَّد من bot.db (الأرقام مطابقة لما كان مكتوباً بتاريخ 2026-10-16).

إضافات (مُعلَّمة «إضافة v2»): القسم 0 في الـ runbook (المسار الافتراضي المقترح)، وملاحظات استعمال `tools/` في القسم 8، وبند 12 في تعليمات الذكاء الاصطناعي، وملاحظة بديلة لجملة HANDOFF.md في القسم 15، وقسم «تحقق إضافي» في ملف الحالة، وملف المقترحات.

## استعمال الأدوات (Python 3.8+ بدون مكتبات)

```
python tools\check_bot.py bot.db --strict                      # فحص: يرجع 1 إذا وُجد ERROR
python tools\check_bot.py bot.db --compare old_bot.db          # مقارنة نسختين حقلاً بحقل
python tools\check_bot.py bot.db --snapshot SNAPSHOT.md        # توليد لقطة الحالة
python tools\bot_db_tool.py export bot.db data                 # bot.db -> ملفات JSON نصية
python tools\bot_db_tool.py build data bot.db --force          # JSON -> bot.db
python tools\bot_db_tool.py verify bot.db data                 # تأكد أن JSON يطابق bot.db تماماً
```

ما اختُبر فعلاً: شُغّل `check_bot.py` على bot.db الحي (يجد الأخطاء الـ18 المعروفة وكل ما في `SNAPSHOT.md`) وعلى نسخة فيها أعطال مزروعة عمداً (خيارات مكررة، `correct_index` خارج النطاق، سطر جديد في الشرح، خيار واحد فقط، سؤال محذوف، تغيير إجابة) فكشفها كلها؛ وجُرّب `bot_db_tool.py` بدورة كاملة export ثم build ثم verify على bot.db الحي (40 مادة و1251 سؤالاً، تطابق كامل لكل صف وعمود). ما **لم** يُختبر: ملف GitHub Actions (لم يُشغَّل على GitHub)، وأي تغيير على Render.

## v2.1 — workflow جديد قيد البناء (أجزاء)

اتُّخذ قرار اعتماد **ملفات نصية `data/`** مصدراً للحقيقة، وبُني الجزء 1 (النواة) واختُبر. التفاصيل والأجزاء الباقية (الصفحة، الأتمتة، التوثيق للطلاب، التجربة الحقيقية) في **`HANDOFF-BUILD.md`**.

| الملف | الغرض |
|---|---|
| `HANDOFF-BUILD.md` | حالة البناء والقرارات والأجزاء الباقية وكيف يكمل حساب آخر |
| `data/` | تصدير نصي (JSON) لـ bot.db الحالي + `provenance/` لمصدر كل إجابة |
| `config/subjects.json` | ربط المواد بمجلدات المحاضرات (المؤكَّدة فقط) |
| `tools/lecturelib.py`, `make_packs.py`, `merge_answers.py`, `selftest.py` | صنع حزم المحاضرات ودمج ردود Claude بعد التحقق من الاقتباس |

```
python tools/selftest.py --data data --lectures ../lecture-site-engine        # اختبار آلي
python tools/make_packs.py --data data --status                                # التغطية لكل مادة
python tools/make_packs.py --data data --lectures ../lecture-site-engine --subject 11 --all
python tools/merge_answers.py --data data --lectures ../lecture-site-engine --replies replies --apply
```
