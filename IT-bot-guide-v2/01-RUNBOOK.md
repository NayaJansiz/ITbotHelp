## ⚡ الطريقة السريعة (2026-10-22) — ارفع PDF وتصدير تيليجرام فقط

هذه هي الطريقة الموصى بها للطالب. كل التحويل يتم في المتصفح، بلا تثبيت وبلا أوامر.

1. افتح الصفحة، اختر **السنة** ثم **المادة**.
2. في بطاقة «⚡ الطريقة السريعة»: اختر **ملف PDF** للمحاضرة (يمكن أكثر من ملف) واكتب **رقم المحاضرة** بجانب كل ملف، ثم اختر **ملفات تصدير تيليجرام** (`messages.html` وما يليه `messages2.html`…).
3. اضغط **«حضّر الملف لـ Claude»**. تظهر أعداد الصفحات والأسئلة (جديد/موجود/مكرر) وأول سطور المحاضرة (تأكد أن العربية سليمة)، ثم ينزّل زر واحد ملفاً واحداً.
4. ملف واحد + الرسالة الجاهزة إلى Claude (محادثة جديدة)، الصق الرد في الصفحة واضغط **تحقّق**.
5. **راجع وعدّل** (الجواب والشرح) من البطاقات: غير الموثّق يظهر أولاً.
6. اضغط **«تنزيل حزمة الـ Pull Request (zip)»** ← Fork للمستودع ← فُكّ الضغط واسحب المجلدات (`replies` و`sources` و`intake`) إلى صفحة الرفع في نسختك ← Commit ← Pull Request.

ما الذي يوفّر التوكنز: Claude لا يرى إلا المحاضرة المرفوعة + أسئلة التصدير. خيار «الجديد وغير المحلول فقط» يحذف الأسئلة المحلولة. لا تُرسل الصور ولا الأشكال.

ما يفعله المشرف: يدمج الـ PR فقط. `data-writer.yml` يشغّل `tools/register_sources.py` (يسجّل المحاضرة الجديدة في `config/sources.json`) ثم `apply_pending.py` (يضيف الأسئلة الجديدة ويطبّق الأجوبة بعد التحقق من الاقتباس).

**حدود يجب قولها:** (1) أسئلة الصور تُحَل نصّاً فقط وتحتاج مراجعة الطالب. (2) صفحات PDF التي هي صور (بلا نص) لا تدخل، والصفحة تعدّها لك. (3) سؤال تغيّر نصّه قليلاً عن المخزَّن يُعامَل «جديداً» ولا يعدّل القديم (آمن، ولا يُحذف شيء). (4) المحاضرة المرفوعة تصير نص المصدر في المستودع: المشرف يطّلع عليها قبل الدمج.

## الطريقة الجديدة (v2.1) — ابدأ من هنا

> هذا هو المسار المعتمد الآن: الأسئلة والأجوبة في ملفات نصية داخل `data/`، و`bot.db` يُبنى منها. الأقسام 1–15 بعد هذا القسم تبقى كمرجع للطرق القديمة والمتقدمة (باتشات `apply_answers.py`، بوت الإدارة، وفحص المحاكاة).
> الفكرة في سطر: **لا يُقبل جواب إلا إذا كان اقتباسه موجوداً حرفياً في نص المحاضرة**، والفحص آلي بلا أي توكن.

### الخطوات

1. **الأسئلة** — إن جاءت من تصدير تيليجرام: `python tools/ingest_polls.py <مجلد التصدير> --year Y --subject N`. يقرأ `messages.html` والصور، ويطابق كل سؤال ببصمة نصّه (السؤال + الخيارات) فلا يتكرر ولا يُفقد.
2. **نص المحاضرة** — مصدران يجتمعان في الصفحة: (أ) مستودع `homs-uni/lecture-site-engine` للمواد المربوطة في `config/subjects.json` (`"folder"`)، و(ب) **ملفات PDF يرفعها الطلاب**: يضيف الطالب الملف إلى `inbox/<رقم المادة>/اسم المحاضرة.pdf` في Pull Request؛ بعد أن **يدمجه المشرف** يعمل `ingest-pdf.yml` فيحوّله إلى `sources/<رقم المادة>/<slug>.md` (+ صفحات الأشكال)، ويسجّله في `config/sources.json`، ويحذف الـ PDF من `inbox/`. المادة هي اسم المجلد الذي اختاره الطالب ووافق عليه المشرف بالدمج، فلا تخمين. (يدوياً: `python tools/ingest_pdf.py <pdf> --subject N --name "<الاسم>"` ثم أضف الـ slug إلى `config/sources.json`؛ يحتاج `pip install pymupdf`.)
3. **بناء الصفحة** — `python tools/build_site.py --data data --lectures ../lecture-site-engine --intake intake` (على GitHub يعمل `pages.yml` تلقائياً)، أو محلياً `python tools/dev_site.py --lectures ../lecture-site-engine --open`.
4. **الطالب** — يفتح الصفحة، يختار السنة ثم المادة، فتظهر **كل محاضرات المادة محدّدة** (يلغي ما لا يريده)، ويضغط زر واحداً «تنزيل كل شيء لـ Claude» (أو «الجزء i من n» إن زاد الحجم عن 250000 حرف)، يرفع الملف إلى Claude مع الرسالة الجاهزة، يلصق الرد، يراجع ويعدّل، ثم ينزّل `all-<sha8>.jsonl` + `all-<sha8>.summary.md` ويرفعهما في Pull Request إلى `replies/<رقم المادة>/`.
5. **المشرف** — يقرأ ملخص التغييرات ويدمج (**الموافقة = الدمج**).

### ما يفعله المشرف

- `pr-check.yml` يفحص كل PR **بلا كتابة وبلا أسرار** (يعمل أيضاً على PR من Fork، والتقرير في تبويب Summary): يتأكد أن الطالب أضاف ملفات جديدة فقط (`intake/ replies/ sources/ media/ inbox/`)، ويشغّل الاختبارات، ويجرّب الدمج `dry run` على `replies/`. أول مرة من مساهم جديد يلزم زر «Approve and run» من المشرف.
- `data-writer.yml` هو **الكاتب الوحيد** لـ `data/`: بعد الدمج يطبّق ملفات `intake/` و`replies/` الجديدة بنفس الفحوص، يعيد فحص الاقتباسات (`reverify.py --mark`)، يبني `build/bot.db`، ويشغّل `check_bot.py`، ثم يعيد بناء الصفحة.
- `ingest-pdf.yml` يحوّل ملفات `inbox/**/*.pdf` المدموجة (انظر الخطوة 2). ملف PDF لا يمكن قراءته يبقى في `inbox/` ويفشل التشغيل ليراه المشرف.
- **PR الطالب يضيف ملفات جديدة فقط** ولا يعدّل ملفاً موجوداً (`tools/check_pr_paths.py` يمنع غير ذلك؛ نسخته من الفرع الأساسي لا من الـ PR).

### الحدود الحالية (يجب قولها للطلاب والمشرفين)

- `bot.db` الحي ما زال بوت الإدارة يكتبه؛ وبناء `bot.db` من `data/` على Render **لم يُنفَّذ بعد**، أي أن الأجوبة المدموجة لا تصل البوت حتى يغيّر مالك Render أمر البناء.
- الصفحة وسير العمل جُرّبا محلياً (واختبار jsdom)، **لم يُجرَّبا على GitHub نفسه ولا في متصفح حقيقي** حتى الآن.
- شرح الجواب ≤ 200 حرف مع علامة `(م#)`، والخيار ≤ 100 حرف، والسؤال ≤ 300 حرف (حدود تيليجرام).

### نشر قاعدة مصحّحة بنيتُها من `data/` (خطوة المالكة وحدها)

الوكيل لا يدفع ولا يلمس Render. عندما يكون `bot.db.new` جاهزاً (مثال: بعد إصلاح 2026-10-21) الخطوات في PowerShell داخل مستودع البوت:

```powershell
cd C:\Users\nayaj\Desktop\IT-bot
python ..\IT-bot-guide-v2\tools\check_bot.py bot.db.new --strict      # يجب 0 ERROR
Copy-Item bot.db.new bot.db -Force
git add bot.db
git commit -m "Fix 3 option issues (y3:p116, y4:m224, y4:net12)"
git push
```

ثم: Render يعيد النشر تلقائياً، وجرّب في تيليجرام سؤالاً واحداً من الأسئلة المعدّلة (`y3:p116` كان يُتخطّى قبل الإصلاح). للتراجع: استعد `bot.db` القديم من سجل git وادفعه. أي commit على هذا المستودع يصل للطلاب فوراً — لا تدفع وأنت غير متأكد.

## الخطوات حسب الحالة
ملاحظة مهمة: سكربتا apply_answers.py وapply_all.py يعدّلان أسئلة موجودة في bot.db فقط (أي key غير موجود يُتخطّى مع رسالة SKIP missing). إدخال أسئلة جديدة كصفوف يتم إما بـ Claude من تصدير تيليجرام (الطريقة 6) أو ببوت الإدارة (الطريقة 7).

### الحالة أ: المحاضرات موجودة والأسئلة نصية
1. اجلب آخر bot.db. git clone --depth 1 https://github.com/nadeembrijawy/IT-bot (أو خذه ممن يملك أحدث نسخة). سجّل حجمه وmd5 وعدد الأسئلة الظاهرة (الأمر في القسم 8 خطوة 5، أو الأداة tools/check_bot.py).
2. صدّر المجموعة. تيليجرام ديسكتوب: افتح المجموعة، القائمة (⋮)، Export chat history، الصيغة JSON، فعّل Photos إن وجدت صور واترك الباقي مطفأ، ثم اضغط مجلد التصدير كله ZIP.
3. افتح محادثة جديدة مع Claude وأرفق: هذا الملف، وZIP المشروع (أو على الأقل bot.db الأحدث)، وZIP التصدير. انسخ الجملة الجاهزة «أول رسالة في كل محادثة جديدة» (ومعها جملة «ضفلي الـ polls الجداد…») من القسم 15 واملأ السنة والفصل والمادة والاختصاص (للسنتين 4 و5: برمجيات أو ذكاء صنعي أو شبكات) ومجلد المحاضرات إن عرفته.
4. Claude يعمل: يستنسخ مستودع المحاضرات، يدخل الأسئلة الجديدة فقط (مفتاح السؤال = رقم رسالة الـ poll، فلا تتكرر الأسئلة القديمة)، يجيب بترتيب المصادر في القسم 9، ويعيد الملفات المحدّثة مع قائمة الأسئلة «للمراجعة» والمستبعدة وسبب الاستبعاد.
5. راجع المشكوك فيها (review_answers.csv) مع دكتور أو زميل، لأن إجابات Claude غير مضمونة 100%.
6. افحص ثم ادفع حسب «خطوات التحديث والدفع على ويندوز» (القسم 8) بعد تشغيل tools/check_bot.py، ثم جرّب البوت: /start ثم السنة ثم الفصل ثم المادة، وتأكد أن الأسئلة الجديدة ظاهرة وأن الشرح يظهر بعد الاختيار.

أولاً ابحث في كل مجلدات المستودع عن كلمات مفتاحية من الأسئلة (قد تكون المادة موزّعة على مجلدات أخرى، كما حدث مع خوارزميات 1)، ثم اختر:
1. حصل على محاضرات المادة بصيغة PDF (مصدر المحاضرات غير مذكور في الملفات المرفقة؛ اسأل المسؤول).
2. المسار ب-1: أضفها إلى مستودع المحاضرات (يفيد الجميع ويحوّل الحالة إلى «أ»): افتح صفحة contrib، اختر المادة، محاضرة جديدة أو رفع ملف، احفظ فيفتح Pull Request إلى main، انتظر نجاح Validate lectures ثم اطلب الدمج. المحاضرة تُكتب بتنسيق SCHEMA.md في subjects/year-N/<مجلد>/lectures/parN.md، وخط الإنتاج المذكور في المستودع هو: subject-brief / SCHEMA / templates ثم custom_prompt.md ثم PDF ثم parN.md. لا تعدّل files في manifest.json يدوياً. إذا كان للمادة مجلد بلا محاضرات أو لا مجلد لها، ضبط settings في manifest.json يتم من المشرف (بدون enabledLectures: true لا تظهر المادة على الموقع). بعد الدمج اتبع الحالة «أ».
3. المسار ب-2: بوت الإدارة (كله داخل تيليجرام، بلا git): افتح @exambankadminbot ثم:
    1. /subject واختر المادة.
    2. أرسل ملفات PDF المحاضرات بتعليق L1 وL2... (وL5 ocr للممسوحة ضوئياً). /lectures تعرض المخزّن، و/drop L5 تحذف.
    3. حوّل (Forward) الـ polls من المجموعة إلى البوت: تُحفظ مخفية وتُطابق مع صفوف bot.db الحية ببصمة (السؤال + الخيارات) وتُتخطّى المكررة.
    4. /bundle (أو /bundle n L5 L6 أو /bundle n all): يبني ملفاً واحداً فيه البرومبت الثابت + الأسئلة + نص المحاضرات + تقدير التوكنات.
    5. ارفع الملف إلى Claude مع العبارة «حلّ المرفق» (حسب ملف onboarding: «solve the attached»)، فيعيد ملف patch.json.
    6. أرسل patch.json إلى البوت، ثم /review واختر Approve / Hold / Exclude لكل جواب.
    7. /publish ثم Confirm: يكتب البوت bot.db إلى المستودع الحي عبر GitHub API، والنجاح يظهر بالعبارة «Published and verified». /undo يستعيد آخر نسخة احتياطية، و/health يفحص الاتصال، و/stats يعرض العدادات.
    8. قواعد الموافقة التلقائية: محاضرة/بنك امتحان + ثقة عالية = يصلح؛ محاضرة متوسطة أو استنتاج عالي = «check»؛ استنتاج متوسط/منخفض وTODO لا يُعتمدان.
   تحذير من المصادر: حسب ملف onboarding (حالة 12 تشرين الأول) لم يكمل /publish بعد بسبب خطأ 403 في الكتابة إلى مستودع البيانات، فتأكد أن /health يعرض data repo write: OK قبل الاعتماد على هذا المسار. ولم يُذكر صراحة هل /publish يضيف صفوفاً جديدة لمادة جديدة أم يكتفي بتحديث الموجود: اسأل المسؤول قبل استعماله لمادة لم تُعرّف بعد.
4. لا توجد محاضرات أبداً: تُوسم الإجابات inferred-from-concept (مثل المواد المذكورة في القسم 11 بلا محاضرات)، والأفضل هنا العمل مع Claude (الحالة أ) لأن بوت الإدارة لا يعتمد الاستنتاج المتوسط أو المنخفض (اقتراح).

## 1. ما هو البوت وكيف يعمل النظام كله
بوت تيليجرام يعرض بنك أسئلة الدورات السابقة لطلاب هندسة المعلوماتية في جامعة حمص (@uni_exams_bot). تظهر الأسئلة للطالب كاختبارات quiz poll، وبعد الإجابة يظهر شرح قصير.
رحلة الطالب: /start ثم السنة، ثم الفصل، ثم الاختصاص (للسنتين 4 و5 فقط)، ثم المادة، ثم أسئلة بدفعات من 10 مع زر «➡️ التالي».
مسار الملفات: GitHub (الفرع main) ثم Render ثم تيليجرام. كل commit على main يعيد نشر البوت. الأسئلة وإجاباتها وشروحها كلها داخل ملف واحد هو bot.db (SQLite) في المستودع، والبوت يقرأ منه فقط.
إحصائيات الطلاب (من فتح أي مادة وماذا أجاب) لا تُحفظ في bot.db. تُحفظ في قاعدة PostgreSQL خارجية (مثل Neon) عندما يكون المتغير DATABASE_URL مضبوطاً، وإلا في ملف stats.db محلي مخصص للتجربة على الكمبيوتر فقط.
كيف تتغير الأسئلة: تحديث الأسئلة أو الإجابات أو الشروح يعني تحديث bot.db على main. توجد ثلاث طرق لذلك، وتفصيلها في الأقسام التالية:
1. العمل مباشرة مع Claude بملفات المشروع (القسم 6).
2. بوت الإدارة على تيليجرام (القسم 7).
3. ملفات الباتش JSON وسكربتات التطبيق (القسم 8).

## 3. القواعد الذهبية
هذه القواعد تنطبق على كل الطرق الثلاث.
1. الأسرار: لا تطلب ولا تكرر ولا تستعمل أي توكن (BOT_TOKEN أو GITHUB_TOKEN). التوكنات تعيش فقط في متغيرات البيئة (env vars) على Render. لا تُرسل في أي محادثة ولا تُوضع في الملفات.
2. مستودع البيانات خاص: يحتوي مادة الدكاترة، فيجب أن يبقى private.
3. مستودعان منفصلان: مستودع الكود ومستودع البيانات يجب أن يكونا مستودعين مختلفين، وإلا فكل حفظ تلقائي (autosave) يعيد نشر البوت.
4. لا تعدّل bot.db بيدك. مرّر كل تعديل عبر Claude أو بوت الإدارة أو ملف باتش.
5. لا ترسل نسخة قديمة من الملفات إلى Claude، وإلا تضيع التعديلات السابقة. احفظ دائماً آخر نسخة رجعت إليك.
6. bot.db ملف ثنائي لا يمكن دمجه (merge). قبل أي دفع (push) اسحب آخر نسخة (git pull)، وإذا تغيّر bot.db على main منذ آخر مرة فتوقف ولا تدفع فوقه. لا تستعمل force.
7. لا تنشئ خدمة Render جديدة. الخدمة الموجودة هي المستعملة.
8. أي commit على المستودع الحي يعيد نشر بوت الطلاب، فتأكد قبل الدفع أن الذي ستدفعه هو الملف الصحيح (الحجم وعدد الأسئلة الظاهرة، القسم 8).
9. اعمل دائماً من نسخة نظيفة (clean clone) من المستودع، لا من مجلد المنزل ولا من نسخة قديمة. في السابق أُنشئ مستودع git بالخطأ في C:\Users\nayaj، فلا تشغّل أوامر git من هناك.
10. إجابات Claude غير مضمونة 100%. الأسئلة المعلّمة «للمراجعة» تعتبر مشكوكاً فيها، وتُراجع مع دكتور أو زميل.
11. لا تخترع مصادر ولا اقتباسات. إذا لم تجد الجواب في المحاضرة أو بنك الدورات، فاذكر ذلك بوضوح (القسم 9).

## 4. كيف يعرض البوت الأسئلة للطالب
هذا القسم مأخوذ من كود bot.py الحالي على main (تم التحقق منه بتاريخ 2026-10-16). إذا تغيّر الكود لاحقاً فالكود هو المرجع.
القوائم. البوت يستعمل أزرار لوحة المفاتيح (Reply Keyboard) وليس أزرار inline. التسلسل: السنة ثم الفصل ثم الاختصاص (للسنتين 4 و5 فقط، ويظهر فقط الاختصاص الذي له مواد ظاهرة: برمجيات أو ذكاء صنعي أو شبكات) ثم المادة. قائمة المواد تضم المواد المشتركة (shared) ومواد الاختصاص المختار، ويظهر بجانب كل مادة عدد أسئلتها الظاهرة. البوت يطابق نص الزر حرفياً (مثل «📖 الفصل الأول»).
الأسئلة التي تظهر. فقط ما له correct_index غير فارغ وexcluded = 0، مرتبة حسب id. سنة أو فصل أو مادة ليس فيها أي سؤال ظاهر لا تظهر في القوائم.
الدفعات. عند اختيار مادة يرسل البوت 10 أسئلة (BATCH = 10)، ثم رسالة «المعروض: X / N | المتبقي: M | اختر «التالي» للمتابعة» مع الأزرار: «➡️ التالي» و«⬅️ رجوع» و«🏠 القائمة الرئيسية». الترقيم يكمل من الدفعة السابقة (11، 12، ...). الدفعة الأخيرة قد تكون أقل من 10، ثم تظهر رسالة «🎉 انتهت جميع الأسئلة».
كل سؤال. يُرسل كـ quiz poll غير مجهول (is_anonymous=False) بالإجابة الصحيحة من correct_index. العنوان = رقم البوت + نص السؤال بعد إزالة الرقم الأصلي من أوله (مثل «29)» أو «5-»)، حتى يبقى ترقيم واحد. الحدود: العنوان 300 حرف، الخيار 100 حرف، الشرح 200 حرف، وأقصى عدد الخيارات 10 (النص الأطول يُقصّ تلقائياً بالكود). الشرح يظهر بعد الاختيار.
الصور. إذا كان للسؤال صورة (حقل image) تُرسل كصورة قبل الـ poll. يبحث البوت عن الملف بالمسار المكتوب في القاعدة (مثل media/y3_photo_9_....jpg)، وإذا لم يجده يبحث عن نفس اسم الملف في جذر المستودع. إذا لم يوجد الملف يسجّل تحذيراً في الـ log ويكمل إرسال السؤال بدون صورة.
أسئلة يرفضها تيليجرام. إذا رفض تيليجرام الـ poll (مثلاً خيارات مكررة أو فارغة) يسجّل البوت تحذيراً في الـ log ويتجاوزه بدون أي رسالة للطالب. لذلك العدد المكتوب على زر المادة قد يزيد عن ما يوصل فعلاً، وهذا سبب اختبار كل سؤال قبل النشر (القسم 8).
النتيجة. بعد أن يُرسل آخر سؤال ويجاوب الطالب على كل أسئلة المادة، تصله رسالة بعدد الصح والغلط والنسبة المئوية.
الذاكرة وإعادة التشغيل. مكان الطالب في القوائم محفوظ في الذاكرة فقط (context.user_data). بعد إعادة نشر أو إعادة تشغيل للبوت، إذا ضغط طالب «التالي» تظهر له رسالة «اختر أحد الأزرار من القائمة» ويبدأ من القائمة من جديد.
التشغيل. يعمل البوت بالـ polling (run_polling)، لذلك يجب أن تعمل نسخة واحدة فقط بنفس التوكن (تشغيل نسخة أخرى على الكمبيوتر بنفس التوكن يتعارض مع Render). ويشغّل خادم صحة بسيط يرد «OK» على المنفذ PORT (الافتراضي 10000) ولا يعرض أي ملف، والتعليق في الكود يذكر أن UptimeRobot يستخدم طلب HEAD. المتغيرات: BOT_TOKEN (إلزامي)، ADMIN_IDS، DATABASE_URL، PORT.
أوامر المسؤولين داخل البوت الحي (لمن أرقامهم في ADMIN_IDS فقط، وغيرهم تُتجاهل أوامرهم):

| الأمر | ماذا يفعل |
|---|---|
| /stats | نظرة عامة على إحصائيات الاستخدام |
| /stats_y2_s1 … (السنة 1–5، الفصل 1–2) | تقرير سنة وفصل محددين |
| /export | يرسل ملف answers.csv بإجابات الطلاب |

| /myid | يعرض الرقم التعريفي (ID) لمن يكتبه (متاح للجميع) |

## 5. قاعدة البيانات bot.db
ملف SQLite واحد في جذر مستودع البوت الحي، فيه جدولان:
subjects(id, year, semester, name, track)
questions(id, key UNIQUE, subject_id, question, options /*JSON list*/, correct_index,
          explanation, needs_review, answer_source, image, long_question, excluded)
• track في subjects: القيم الموجودة فعلاً هي shared (مشترك) وsoftware (برمجيات) وai (ذكاء صنعي) وnetworks (شبكات).
• شرط ظهور السؤال للطالب: correct_index IS NOT NULL AND excluded = 0. السؤال المخفي (hidden) هو ما خالف هذا الشرط، وعادةً تكون إجابته فارغة (NULL) وexcluded = 1. عند النشر يجب ضبط excluded = 0 حتى يظهر السؤال.
• correct_index: رقم الخيار الصحيح داخل قائمة options، ويبدأ من 0 (الخيار الأول = 0).
• options: قائمة JSON نصية. لا يسمح بتغييرها في الباتش إلا عبر حقل new_options المذكور في القسم 8.
• المفاتيح (key): مثل y3:p165546 = السنة + رقم رسالة الـ poll في ملف تصدير تيليجرام، أو y{السنة}:a{رقم} للأسئلة التي أنشأها بوت الإدارة. مفتاح كل سؤال فريد، لذلك لا تُعاد الأسئلة التي انحلت من قبل.
• image: مسار الصورة، مثل media/y3_photo_9_....jpg، والصور نفسها موجودة في مجلد media بالمستودع. بوت الإدارة لا يستطيع معالجة أسئلة الصور، فتُعلّم TODO.
• needs_review وanswer_source: حقول توثيقية للمراجعة، وbot.py لا يستعملهما (لا تؤثران على ما يراه الطالب).
• الشرح (explanation): حده 200 حرف (عربي). الحدود الكاملة في القسم 10.
هل هذا هو الملف الصحيح؟ قبل أي عمل، إذا وجدت أكثر من نسخة من bot.db (في مجلدات أو ملفات zip)، قارن كل نسخة بالحجم وبصمة md5 وعدد الأسئلة الكلي والظاهرة، ولا تخمّن أيها الأحدث من الاسم أو من ملفات ملاحظات قديمة. في حالة سابقة كانت ملفات الملاحظات تقول إن نسخة الجذر هي الأفضل، بينما تبيّن أن نسخة داخل مجلد Desktop هي التي فيها كل التعديلات (1092 سؤالاً ظاهراً مقابل 1084).

بعد كل جلسة احفظ النسخة المحدّثة التي رجعها Claude، وفي المحادثة الجاية ابعت هذه النسخة. إذا بعتت نسخة قديمة فالتعديلات التي صارت تضيع.

### إضافة أسئلة جديدة
1. في تيليجرام ديسكتوب افتح الغروب الذي فيه الـ polls، ثم القائمة (⋮)، ثم Export chat history.
2. اختر الصيغة JSON. فعّل Photos إذا في أسئلة فيها صور، وخلّي الباقي (فيديو، ملفات...) مطفي.
3. ضغط مجلد التصدير كله ZIP (ملف result.json مع مجلد الصور).
4. ابعت الـ ZIP لـ Claude مع ملف البوت، واكتب له وين تنزل الأسئلة: السنة، الفصل، المادة، وإذا سنة 4 أو 5 الاختصاص (برمجيات / ذكاء صنعي / شبكات).
5. Claude يحل الأسئلة الجديدة فقط. مفتاح كل سؤال هو رقم رسالة الـ poll، فالأسئلة التي انحلت قبل لا تُعاد.
6. يرجع لك الملفات المحدّثة، مع قائمة بالأسئلة المعلّمة «للمراجعة» والأسئلة المستبعدة وسبب الاستبعاد.
7. راجع المشكوك فيها، وبدّل الملفات بالبوت (الفقرة «بعد استلام الملفات» أدناه)، وجرّب.
الأسئلة التي تعتمد على كود أو جدول أو شكل، أو التي خياراتها مقطوعة، تُستبعد. إذا بعت صور الجدول أو الكود ممكن ينحلوا لاحقاً.

### تعديل سؤال
ابعت لـ Claude نص السؤال (أو مفتاحه مثل y3:p1234) وقله شو بدك يتغير. ما بتحتاج export جديد.

| ماذا تعدّل | مثال للجملة | الحد |
|---|---|---|
| الإجابة الصحيحة | «الإجابة الصحيحة هي الخيار الثالث» | - |
| الشرح | «غيّر الشرح لـ ...» | 200 حرف |
| نص السؤال | «عدّل نص السؤال لـ ...» | 300 حرف |
| خيار | «الخيار الثاني صار ...» | 100 حرف |
| المادة أو الفصل | «انقل السؤال لمادة ... فصل 2» | - |

الأفضل أن تنسخ السؤال من تيليجرام أو من البوت نفسه حتى يجده Claude بدون لبس. إذا في سؤالين متشابهين اكتب جزءاً من الخيارات.

### شطب (استبعاد) سؤال
بدل ما يُمسح السؤال نهائياً، يعلّمه Claude «مستبعد» في ملف الإجابات، فيختفي من البوت ويقدر يرجع إذا بدك. اكتب له:
• «استبعد هالسؤال: ...» لسؤال واحد.
• «استبعد كل أسئلة مادة ... فصل ...» لمادة كاملة، وهون بيسألك تأكيد قبل ما يعمل.
• «رجّع السؤال المستبعد ...» لإرجاع سؤال.
الأسئلة المستبعدة تُكتب في ملف excluded_questions.csv.

### بعد استلام الملفات: تحديث البوت
1. خد نسخة احتياطية من مجلد البوت الحالي قبل أي تبديل.
2. بدّل الملفات التي رجعها Claude: bot.db وanswers.json وquestions.json. إذا في أسئلة بصور جديدة، انسخ الصور لمجلد media.
3. إذا البوت مستضاف (مثل Render)، بدّل نفس الملفات بنسخة الاستضافة (render_bot) وأعد النشر.
4. أوقف البوت وشغّله من جديد (على ويندوز: set BOT_TOKEN=... ثم python bot.py).
5. جرّب: /start، ثم المادة التي تعدّلت، وتأكد أن الأسئلة الجديدة والتعديلات ظاهرة وأن الشرح يطلع بعد الاختيار.
البوت يقرأ من bot.db، وتعديل answers.json لحاله بدون bot.db لا يظهر في البوت. التوكن سرّي، لا تبعته في أي محادثة ولا تحطه بالملفات.

## 7. الطريقة الثانية: بوت الإدارة على تيليجرام
مأخوذة من ملف «Teammate onboarding» (حالة 12 أكتوبر 2026). بوت الإدارة يعمل كله داخل تيليجرام بدون terminal وبدون git. Claude (في المحادثة) يحل الأسئلة، والبوت يقوم بكل ما عدا ذلك.

### المسار خطوة خطوة
1. أعد توجيه (forward) الـ quiz polls إلى بوت الإدارة. تُحفظ مخفية، وتُطابق مع صفوف bot.db الحي ببصمة (fingerprint) السؤال + الخيارات، والمكرر يُتجاهل.
2. أرسل ملفات PDF للمحاضرات (مع تعليق مثل L5، أو L5 ocr للمسوحات ضوئياً).
3. /bundle: يجهّز ملفاً واحداً فيه الـ prompt الثابت + الأسئلة + نص المحاضرات + تقدير عدد التوكنات.
4. ارفع الملف إلى Claude واكتب: «solve the attached».
5. يعيد Claude ملف patch.json. أرسله إلى بوت الإدارة.
6. /review: لكل إجابة ثلاثة خيارات: Approve (موافقة) أو Hold (تأجيل) أو Exclude (استبعاد).
7. /publish ثم Confirm: يكتب البوت bot.db إلى المستودع الحي عبر GitHub API.

### صيغة الباتش الذي يعيده Claude لبوت الإدارة
كل عنصر: {key, correct_index|null, explanation(<=200, Arabic), source, confidence, citation, note}، حيث source إحدى: lecture-text أو exam-bank أو inferred-from-concept أو TODO، وcitation بشكل L1.3: "اقتباس حرفي".
يرفض بوت الإدارة: اقتباسات ليست موجودة حرفياً على الشريحة المذكورة، وخيارات تغيّرت، وشروحات أطول من 200 حرف.

| الحالة | قاعدة الموافقة في بوت الإدارة |
|---|---|
| lecture أو exam + high | يُقبل (OK) |
| lecture + medium أو inferred + high | «تحقق» (check) |
| inferred + medium/low وTODO | لا يمكن الموافقة عليها |

### أمان النشر (مبني مسبقاً في البوت)
يجلب نسخة bot.db الحالية مع الـ SHA، يطبّق على نسخة، يفحص سلامة الملف (integrity check)، يعرض ملخصاً مع Confirm، يأخذ نسخة احتياطية إلى مستودع البيانات، يعمل commit بالـ SHA (وإذا تغيّر الملف في الأثناء يرفض)، يقرأ ما كتبه ويتحقق، ولا يعلّم الأسئلة «منشورة» إلا بعد التحقق. و/undo يرجع آخر نسخة احتياطية.

### محوّل المحاضرات (convert_lectures.py)
الوضع التلقائي يعتمد على منشئ الـ PDF (pdfinfo creator): ملفات PowerPoint تستخدم وضع الشرائح (pdftotext -raw، إزالة التكرار، علامات §L5.12)، والبقية تستخدم الوضع الهجين (hybrid). مشاكل معروفة: ملفات PowerPoint العربية تخرج كلمة واحدة في كل سطر وبعض الكلمات بترتيب معكوس؛ الشرائح الصورية تُعلّم فقط إذا كان النص أقل من 120 حرفاً؛ والـ OCR العربي يحتاج حزمة ara (موجودة في Dockerfile).

## 8. الطريقة الثالثة: ملفات الباتش وسكربتات التطبيق
هذه هي الطريقة التي استُعملت لحل مواد كاملة (السنوات 1 إلى 3) من خلال محادثات مع Claude مع ملف انتقال (handoff). المصدر: handoff-v3.md وما جرى في الجلسات.

### الفكرة
لكل مادة: يجيب Claude على كل أسئلتها (حتى المحلولة سابقاً، لترقية الشروح القصيرة جداً)، ويظهِر المخفي منها حيث أمكن، ويسلّم ملف باتش JSON يُطبّق بسكربت apply_answers.py. القرار المتفق عليه: حل الكل، واستبدال إجابة قاعدة البيانات عندما تكون إجابة Claude أفضل دعماً، مع ذكر كل تعارض في تقرير المادة.

### صيغة ملف الباتش (لـ apply_answers.py)
قائمة JSON، عنصر لكل سؤال:
{key, subject_id, correct_index, explanation (<=200, Arabic), options (must equal the DB options),
 source (lecture-text | exam-bank | inferred-from-concept | image-derived | TODO),
 confidence (high|medium|low|none), citation (review only, never written),
 db_correct, db_excluded}
• new_options (اختياري، بنفس عدد الخيارات): يُكتب في القاعدة بعد مطابقة الخيارات القديمة. استُعمل مرة لتصحيح سؤال خياراته مكررة رفضها تيليجرام (y3:p116).
• عناصر TODO: correct_index وexplanation فيها null.
• ملاحظة: هذه الصيغة مختلفة عن صيغة بوت الإدارة (القسم 7). لا تخلط بينهما.

### السكربتات
apply_answers.py <patch.json> (تجربة افتراضية dry run إلا إذا أضفت --apply):
• --apply: يكتب فعلياً، ويأخذ أولاً نسخة احتياطية bot.db.bak-<الوقت>.
• يحدّث الشروح. يملأ الإجابة المفقودة فقط إذا كانت الثقة أعلى من أو تساوي --min-confidence (الافتراضي medium).
• --unhide: يظهِر الأسئلة التي مُلئت إجابتها.
• --overwrite-answers: الوحيد الذي يغيّر إجابة موجودة. بدونه تُطبَع التعارضات فقط (CONFLICT …) دون تطبيقها، ومعه تُطبَع وتُطبَّق.
• يتجاهل (SKIP) أي عنصر مفتاحه غير موجود، أو خياراته تختلف عن القاعدة، أو شرحه أطول من 200 حرف. أي SKIP معناه توقف وراجع.
apply_all.py: يشغّل apply_answers.py على كل patch_*.json في المجلد. بدون خيارات = معاينة فقط؛ --apply = يكتب ويُفعّل تلقائياً --unhide و--overwrite-answers؛ --low = يخفض حد الثقة إلى low فتظهر الإجابات منخفضة الثقة. المنطقي معاينة أولاً ثم --apply.
نمط البناء الذي استُعمل: تفريغ أسئلة المادة من القاعدة إلى JSON، ثم الإجابة على كل سؤال (الفهرس + الشرح + المصدر + الثقة + الاستشهاد)، ثم التحقق (الطول <= 200، الفهرس ضمن عدد الخيارات)، ثم كتابة الباتش، ثم تجربته على نسخة من القاعدة، ثم فحص عدد الأسئلة الظاهرة.

### فحص قبل النشر (محاكاة الـ polls)
بعد أي تعديل كبير شغّل فحصاً لكل سؤال ظاهر: عدد الخيارات >= 2، لا خيار فارغ ولا مكرر، correct_index أقل من عدد الخيارات، الشرح <= 200 حرف وليس فيه أكثر من سطرين جديدين، وملف الصورة موجود إن وجدت صورة. السبب: إذا رفض تيليجرام الـ poll يكتفي البوت بتسجيل تحذير ويتجاوز السؤال (القسم 4).

> **إضافة v2** (ليست من المصادر الأصلية للدليل): فحص المحاكاة أعلاه صار سكربتاً جاهزاً: `tools/check_bot.py` (يطبّق نفس القواعد على كل سؤال ظاهر، ويفحص وجود ملفات الصور مثل `bot.py` تماماً). شغّله قبل أي دفع.

### خطوات التحديث والدفع على ويندوز (PowerShell)
نفّذ كل أمر لوحده وانتظر نتيجته. المجلد IT-bot-final مجرد اسم مثالي لنسخة نظيفة جديدة، اختر اسماً لا يتعارض مع نسخك القديمة.
1. افتح PowerShell داخل مجلد Downloads: افتح المجلد في مستكشف الملفات، انقر شريط العنوان، اكتب cmd أو powershell ثم Enter.
2. نسخة نظيفة جديدة (أول مرة):
   git clone https://github.com/nadeembrijawy/IT-bot.git IT-bot-final
   إذا سبق أن عملت النسخة، ادخل مجلدها ونفّذ git pull بدلاً من ذلك.
3. أين أنت؟ داخل نفس النافذة: cd C:\Users\nayaj\Downloads\IT-bot-final (في PowerShell لا تكتب /d)، ثم git rev-parse --show-toplevel يجب أن يطبع مساراً ينتهي بـ IT-bot-final. إذا ظهرت تحذيرات مثل could not open directory 'Application Data/': Permission denied فهذا يعني أنك في مجلد المنزل وليس داخل المستودع: توقف ولا تشغّل git add.
4. ضع الملف الجديد: انسخ bot.db الجديد إلى مجلد النسخة واختر «استبدال الملف». إذا سمّى المتصفح الملف مثل bot (1).db فأعد تسميته إلى bot.db بالضبط.
5. تحقق من أنه الملف الصحيح:
   (Get-Item bot.db).Length
   python -c "import sqlite3;c=sqlite3.connect('bot.db');print(c.execute('select count(*) from questions where correct_index is not null and excluded=0').fetchone())"
   يجب أن يطابق الحجم والعدد اللذين أعطاهما Claude. إذا لم يطابقا فأنت لم تضع الملف الصحيح، كرّر الخطوة 4.

> **إضافة v2** (ليست من المصادر الأصلية للدليل): بدل أمر python اليدوي أعلاه (أو معه) يمكنك تشغيل الأداة الجاهزة من مجلد النسخة النظيفة:

```
python tools\check_bot.py bot.db --strict
python tools\check_bot.py bot.db --compare <مسار-نسخة-bot.db-القديمة-من-main>
```

الأول يطبع الأخطاء (ERROR) والتحذيرات (WARNING) ويرجع رمز خروج 1 إذا وُجد خطأ؛ **لا تدفع وفي الفحص ERROR**. الثاني يقارن النسختين حقلاً بحقل (مفاتيح مضافة/محذوفة، وتغيّر correct_index أو options أو explanation أو excluded على أسئلة موجودة) ويطبع الأحجام وmd5 والأعداد للنسختين. يبحث عن مجلد `media/` بجانب `bot.db`، فشغّله داخل النسخة النظيفة بعد نسخ الصور.

6. انظر ما سيتغيّر: git status يجب أن يظهر bot.db فقط معدّلاً (مع أي ملفات محذوفة أنت قصدت حذفها). إذا ظهرت ملفات أخرى فتوقف. إذا كانت مجلدات قديمة مثل Desktop أو Downloads (نسخ قديمة من bot.db) موجودة في المستودع فاحذفها بـ git rm -r Desktop Downloads (تم ذلك مرة، ولا تظهر في المستودع الحالي).
7. ادفع:
   git add bot.db
   git commit -m "وصف قصير للتحديث"
   git push
   النجاح ينتهي بسطر مثل main -> main. إذا رُفض الدفع (fetch first أو non-fast-forward) فهذا يعني أن شخصاً آخر دفع شيئاً في الأثناء: لا تستعمل force، انسخ الرسالة وراجعها.
8. التحقق من النشر: المسؤول عن Render يتأكد أن الخدمة أعادت النشر من هذا الـ commit، ثم جرّب في تيليجرام: /start ثم السنة ثم الفصل ثم المادة. إذا بقي البوت قديماً بعد النشر، فقد يكون هناك قرص دائم (persistent disk) على Render فيه نسخة bot.db خاصة به.
9. التراجع: استعد النسخة القديمة من bot.db (من سجل git أو أقدم نسخة .bak) وادفعها.

### إذا طبّقت الباتش بنفسك (بدل أن يطبّقه Claude)
1. ضع ملفات patch_*.json وapply_answers.py وapply_all.py بجانب bot.py وbot.db (النسخة الأحدث من main).
2. معاينة: python apply_all.py. توقف عند أي SKIP، واقرأ كل CONFLICT وقرر إن كان تغيير الإجابة مقبولاً.
3. تطبيق: python apply_all.py --apply (أضف --low إذا أردت إظهار الإجابات منخفضة الثقة).
4. تحقق من عدد الأسئلة الظاهرة بأمر python المذكور أعلاه.
5. احذف نسخ النسخ الاحتياطية التي أنشأها السكربت (del bot.db.bak-*)، ثم كمّل من الخطوة 6 أعلاه (git add bot.db فقط، لا تضف ملفات الباتش والسكربتات للمستودع).
6. احتفظ بملفات الباتش والسكربتات في مجلد احتياطي خاص بك خارج المستودع (مثلاً patches-backup): البوت لا يحتاجها، لكنها تفيد إذا استُبدلت bot.db بنسخة قديمة أو لتسجيل ما تغيّر.
